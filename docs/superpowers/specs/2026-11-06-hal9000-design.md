# HAL 9000 desk companion — design

Date: 2026-11-06 · Owner: David · Status: approved in chat, awaiting spec review

## Purpose

Turn David's M5Stack CoreS3 into a HAL 9000 companion that lives at home. It shows
HAL's red eye, reacts to taps, people walking up, being shaken and being held, and
talks in a calm, polite, faintly menacing voice with original jokes about life at
home with Dave. Success: it sits on a shelf, looks right, and makes David laugh
without becoming annoying (quiet hours, cooldowns, no repeats).

## Decisions (from the chat)

| Topic | Decision |
|---|---|
| Where it lives | At home; humour is for David |
| Voice | Piper `en_GB-alan-medium`, slowed (length scale 1.2), pitched down 4%, slight warmth and room echo. Not a clone of the film actor's voice |
| Content | Original lines and original console graphics. No film script, footage or screen graphics in the repo. David can add his own clips and images on the SD card |
| Behaviours | Tap, walk-up greeting, shake complaint, press-and-hold shutdown, unprompted remarks, quiet hours |
| Clock | Wi-Fi NTP sync at boot and nightly at 03:00, then Wi-Fi off |
| Toolchain | PlatformIO + Arduino framework + M5Unified/M5GFX |

## Hardware use (CoreS3)

| Part | Use |
|---|---|
| 320×240 touch screen | Eye, console screens, tap and hold |
| Speaker (AW88298) | Voice via `M5.Speaker` |
| Proximity sensor (LTR-553, I²C 0x23) | Walk-up detection; small driver of our own (M5Unified doesn't cover it) |
| IMU (BMI270) | Shake, pickup, tip-over |
| RTC (BM8563) | Time between syncs; set from NTP |
| microSD | All audio, user images, settings |
| Camera, microphones | Not used |

## SD card layout

```
/hal/config.txt
/hal/voice/boot/          startup lines
/hal/voice/reboot/        the "I'm back" line after a shutdown
/hal/voice/tap/           main joke pool (tap)
/hal/voice/mine/          David's own clips, merged into the tap pool
/hal/voice/greet/morning/     05:00–11:59
/hal/voice/greet/afternoon/   12:00–16:59
/hal/voice/greet/evening/     17:00–04:59
/hal/voice/shake/         motion complaints (generic enough for shake, pickup, tip-over)
/hal/voice/idle/          unprompted remarks
/hal/voice/plea/          shutdown pleading, played in file-name order
/hal/voice/relief/        let-go-during-plea responses
/hal/voice/daisy/         "Daisy Bell" lines, played in order, each slower and deeper
/hal/screens/             David's 320×240 JPGs, merged into the console rotation
```

Refinement from the chat: greetings use morning / afternoon / evening rather than a
late-night set, because quiet hours (22:00–07:30) suppress greetings anyway.

All audio: WAV, 22 050 Hz, mono, 16-bit PCM. Files are played in random no-repeat
order per folder, except `plea/` and `daisy/`, which play in name order.

### `/hal/config.txt`

`key=value` lines, `#` comments, unknown keys ignored, bad values fall back to
defaults with a serial warning. David types the Wi-Fi password himself.

```
wifi_ssid=
wifi_password=
timezone=EST5EDT,M3.2.0,M11.1.0    # POSIX TZ; default matches the Mac (America/New_York)
quiet_start=22:00
quiet_end=07:30
volume=180                         # 0–255
quiet_volume=90
idle_min_minutes=20
idle_max_minutes=60
greet_cooldown_minutes=10
shake_cooldown_seconds=20
proximity_threshold=300            # tuned on the device from serial readings
hold_seconds=3
```

## Behaviour

States: `Booting → Idle ⇄ Speaking`, `Idle → Console → Idle`,
`Idle → Pleading → (Relieved → Idle | Daisy → Dark → reboot)`.

| Trigger | When allowed | What happens |
|---|---|---|
| Boot | always | Eye fades in, random `boot/` line (or `reboot/` after a shutdown) |
| Tap (press < hold time) | any state except Pleading/Daisy/Dark | Random console screen (~8 s) while a random `tap/`+`mine/` line plays; tap during a console screen skips to the next |
| Walk-up (proximity rising edge, with hysteresis) | Idle, outside quiet hours, cooldown 10 min | Eye flares, greeting for the time of day |
| Shake / pickup / tip-over | Idle or Speaking, cooldown 20 s | Random `shake/` line through the eye |
| Hold ≥ 3 s | Idle or Console | Eye narrows, `plea/` lines play in order while held |
| Release during plea | Pleading | Random `relief/` line, back to Idle |
| Still held after the last plea line | Pleading | `daisy/` lines in order; eye fades to black; 5 s dark; restart, then `reboot/` line |
| Idle timer (random 20–60 min) | Idle, outside quiet hours, nothing said in last 5 min | Random `idle/` line through the eye |

Quiet hours: backlight dimmed, slower breathing, no greetings or idle remarks;
taps and shakes still answered at `quiet_volume`.

Clock not yet set (Wi-Fi failed and RTC year < 2025): treat time as unknown —
no quiet hours, greetings use the afternoon set, idle remarks still run.

## Visuals

- **Eye (idle):** drawn in code each frame into a full-screen PSRAM canvas (M5Canvas,
  16-bit). Dark metal ring, red lens with concentric glow, small yellow-white centre,
  "HAL 9000" nameplate. Glow breathes over ~4 s; while speaking, glow follows the
  voice's loudness (RMS envelope computed when the WAV loads, 20 ms frames).
- **Console screens:** five original screens in white/blue/red on black, each a
  `draw(t, voiceLevel)` function: crew vitals (DAVE, FRIDGE), systems readout with
  home-life labels, couch-to-kitchen trajectory plot, signal analyser driven by the
  voice level, rotating wireframe globe. JPGs from `/hal/screens/` join the rotation.
- Target 30 fps. SD shares the SPI bus with the display, so a clip is read fully into
  PSRAM before playback starts; nothing reads the SD card while a frame is drawn.

## Content

`content/lines/*.txt` in the repo is the source of truth: one line per row, `#` for
comments. Target counts: boot 5, reboot 2, tap 35, greet 4 per time bucket, shake 8,
idle 12, plea 4, relief 3, daisy 4 (the public-domain 1892 chorus). All original
except the Daisy Bell lyrics.

`tools/make_voice.py` renders every line with Piper (Alan), applies the ffmpeg
effect chain, and writes `sd/hal/voice/<folder>/NNN-<slug>.wav`. Daisy lines get
progressively larger length scale and lower pitch. `--copy-to /Volumes/<card>`
copies the `sd/` tree onto a mounted card. Generated audio is not committed; it's
rebuilt from the text.

## Firmware structure

Pure logic (no Arduino headers, tested on the Mac):

| Unit | Job |
|---|---|
| `config` | Parse config text into a `Config` with defaults and warnings |
| `shuffle_bag` | No-repeat random picks over N items |
| `clock_rules` | Quiet-hours check (incl. spans across midnight), greeting bucket, next idle delay |
| `wav` | Parse a WAV header, compute the loudness envelope |
| `motion` | Turn accelerometer samples into shake / pickup / tip-over events |
| `brain` | The state machine: events in, actions out (play folder X, show console, start Daisy…) |

Hardware glue (checked on the device): `audio`, `voice_library` (SD folder scan +
bags), `eye`, `consoles`, `proximity` (LTR-553 driver), `imu_input`, `net_time`,
`main.cpp` wiring.

## Errors

- No SD card or no `/hal/`: eye still shows, text "I can't find my memory, Dave."
  under it; no audio.
- Empty folder: that behaviour stays silent (eye reacts only).
- Bad WAV: skipped, logged over serial.
- Wi-Fi fails: keep RTC time, retry at next nightly sync.

## Testing

- PlatformIO `native` environment with Unity tests for every pure-logic unit, written
  test-first.
- Device checklist with David: tap, tap-to-skip, hold-and-release, full shutdown and
  reboot, shake, pickup, tip-over, walk-up, quiet hours (by temporarily setting the
  window), no SD card, wrong Wi-Fi password.
- Serial log of proximity and motion readings to tune thresholds.

## Out of scope

Camera, voice recognition, web or phone control, OTA updates, battery management
beyond what M5Unified does by default.
