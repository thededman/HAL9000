# Setting up HAL from scratch

This guide takes you from an empty folder to a working desk HAL (M5Stack CoreS3). HAL Zero
(M5Stack Cardputer Zero) and the link between the two are optional and come after.

**Tested on:** macOS on Apple silicon. **Linux** uses the same commands with the differences
noted in each step, but nobody has run it on a Linux PC yet, so please report what you find.
**Windows is not covered.**

## What you need

**Hardware**

| For | You need |
|---|---|
| The desk HAL | An M5Stack CoreS3, a microSD card of 32 GB or less, a card reader, a USB-C data cable |
| HAL Zero (optional) | An M5Stack Cardputer Zero on the same Wi-Fi network as your computer |

**Software on your computer**

| Tool | Why | macOS | Linux (Debian/Ubuntu) |
|---|---|---|---|
| git | get the code | Xcode Command Line Tools: `xcode-select --install` | `sudo apt install git` |
| Python 3.10–3.14 | PlatformIO and the voice tool (3.11 is what's used here) | `brew install python@3.11` | `sudo apt install python3 python3-venv` |
| A C++ compiler | the logic tests and the simulator | comes with the Command Line Tools | `sudo apt install build-essential` |
| ffmpeg | levels and shapes HAL's voice | `brew install ffmpeg` | `sudo apt install ffmpeg` |
| Docker | builds HAL Zero (only if you have a Cardputer Zero) | Docker Desktop | Docker Engine |
| rsync and ssh | copy HAL Zero's files to the Cardputer | built in | `sudo apt install rsync openssh-client` |
| SDL2 | the simulator window (optional) | `brew install sdl2` | `sudo apt install libsdl2-dev` |
| Ollama and a chat model | the AI brain (optional, step 9) | the Ollama app from ollama.com | the install script on ollama.com |
| whisper.cpp (`whisper-cli`) | the AI brain hears you speak (optional, step 9) | `brew install whisper-cpp` | build it from github.com/ggml-org/whisper.cpp |

## 1. Get the code

```bash
git clone https://github.com/thededman/HAL9000.git
```

```bash
cd HAL9000
```

Every command below is run from this folder.

## 2. Install PlatformIO and run the tests

PlatformIO builds the firmware. Install it in its usual place:

```bash
python3.11 -m venv ~/.platformio/penv && ~/.platformio/penv/bin/pip install platformio
```

The ESP32 tools need Python 3.10–3.14. A PlatformIO installed some other way (Homebrew, for
example) may run on a newer Python and fail, which is why this guide always calls
`~/.platformio/penv/bin/pio`.

Check everything works by running the logic tests (no device needed):

```bash
~/.platformio/penv/bin/pio test -e native
```

It should end with a line saying every test case succeeded.

**Linux:** to flash over USB you need permission for serial ports. Add yourself to the
`dialout` group (`sudo usermod -aG dialout $USER`, then log out and in) and install
PlatformIO's udev rules (see "99-platformio-udev.rules" in PlatformIO's documentation).

## 3. Make HAL's voice

HAL's lines are text files in `content/`. A tool turns them into WAV files with
[Piper](https://github.com/OHF-Voice/piper1-gpl), a text-to-speech program that runs on
your own computer.

```bash
python3.11 -m venv tools/.venv
```

```bash
tools/.venv/bin/pip install -r tools/requirements.txt
```

```bash
tools/.venv/bin/python tools/make_voice.py
```

- The first run downloads the voice (64 MB) from Hugging Face into `tools/models/`. It is
  [HAL-9000-Piper-TTS](https://huggingface.co/campwill/HAL-9000-Piper-TTS), a third-party
  voice trained on the film's audio. It is not part of this repository or its licence.
- The lines are written to `sd/hal/voice/` (not tracked by git). Rendering all of them takes
  well under a minute.
- To change what HAL says, edit the files in `content/lines/` and run it again. Your own
  clips (mp3, m4a, wav) can be mixed in with `--mine-from <folder>`.

## 4. Prepare the SD card

1. Format the card as **FAT32** (the CoreS3 can't read exFAT). Use a card of 32 GB or less.
2. Copy HAL's files onto it. Replace the path with where your card is mounted:

   ```bash
   tools/.venv/bin/python tools/make_voice.py --skip-render --copy-to /Volumes/YOURCARD
   ```

   On Linux the card is usually at `/media/$USER/YOURCARD`. The tool only writes inside
   `/hal/` on the card. A new card gets a settings file from the template; an existing
   `/hal/config.txt` is never overwritten.
3. Open `/hal/config.txt` on the card in a text editor and fill in:
   - `wifi_ssid` and `wifi_password`: HAL uses Wi-Fi to set his clock.
   - `timezone`: a POSIX time-zone string. The default is US Eastern.
4. Eject the card safely and put it in the CoreS3.

What ends up on the card:

```
/hal/config.txt        Wi-Fi, time zone, quiet hours, volume, sensitivity, link
/hal/voice/...         HAL's lines (generated by tools/make_voice.py)
/hal/voice/screens/    lines that belong to one console screen
/hal/voice/dialogue/   the desk HAL's half of each conversation with HAL Zero
/hal/voice/mine/       your own clips, mixed into the tap jokes
/hal/screens/          your own 320×240 JPG images, mixed into the console screens
/hal/banner.png        optional: your banner above the eye (PNG or JPG, up to 320×38)
```

macOS leaves hidden `._` files next to what it copies. HAL ignores them.

## 5. Flash the desk HAL

Plug the CoreS3 into your computer with the USB-C cable, then:

```bash
~/.platformio/penv/bin/pio run -e cores3 -t upload
```

The first build downloads the ESP32 tools and takes a few minutes. When it finishes, HAL
restarts: you should see the red eye and hear a greeting. If he says he can't find his
memory, the card is missing, isn't FAT32, or has no `/hal/voice/` folder.

If the upload can't find the device, put the CoreS3 in download mode (hold its reset button
for about two seconds until the green light comes on) and run the command again.

To watch his log and sensor readings:

```bash
~/.platformio/penv/bin/pio device monitor
```

While the monitor is open you can type single letters to test without touching HAL: `T`
tap, `N` tap and show the next screen in order, `H` hold on/off, `P` wave, `K` shake, `W` a
Wi-Fi network that doesn't exist (he should give up after 15 s), `S` a raw screenshot.

That's the desk HAL done. The [README](../README.md) explains how to use him.

## 6. HAL Zero on the Cardputer Zero (optional)

HAL Zero is a Linux program. You build it on your computer in Docker and copy it to the
Cardputer over Wi-Fi.

### 6.1 Reach the Cardputer by SSH

The tools expect to log in as `pi@cardputerzero.local` with an SSH key, with no password
prompt:

```bash
ssh-copy-id pi@cardputerzero.local
```

```bash
ssh pi@cardputerzero.local hostname
```

- If the login is refused, look on the Cardputer (using its own keyboard and terminal) in
  `/etc/ssh/sshd_config.d/`. On our unit a file named `rename_user.conf` blocked SSH logins
  until it was removed and SSH restarted (`sudo systemctl restart ssh`).
- A different user or address: put `HOST=user@address` in front of each `tools/cardputer.sh`
  command. The launcher entry assumes the user is `pi` (`tools/cardputer/hal-zero.desktop`).

### 6.2 Build

```bash
tools/cardputer.sh build
```

Docker has to be running first (on macOS, start Docker Desktop). The first run builds a
Docker image (Debian 13, arm64, like the device) and takes a few minutes; later builds take
seconds.

**Intel or AMD computers** have to emulate arm64, which is slower. Enable it once with
`docker run --privileged --rm tonistiigi/binfmt --install arm64`.

### 6.3 His voice and conversations

```bash
tools/.venv/bin/python tools/make_voice.py --model new
```

```bash
tools/.venv/bin/python tools/make_voice.py --dialogues
```

```bash
tools/.venv/bin/python tools/make_voice.py --skip-render --push-to pi@cardputerzero.local
```

The last command mirrors `build/new/hal/voice/` and `dialogues/` to `~/hal` on the
Cardputer. **Render everything first:** it removes files on the Cardputer that aren't in
your local copy. It never touches `~/hal/config.txt` or your own clips in `voice/mine/`.

### 6.4 Install and run

```bash
tools/cardputer.sh deploy
```

```bash
tools/cardputer.sh install
```

- `deploy` copies the program, its start script and, if there is none yet, a settings file
  (`~/hal/config.txt`).
- `install` adds HAL Zero to M5Stack's launcher. It asks for the Cardputer user's sudo
  password, and is only needed once.
- Start HAL Zero from the launcher. M5Stack's launcher is paused while he runs and comes
  back when he quits (Esc).

Handy while developing: `tools/cardputer.sh run` starts him over SSH (`run --show diagnostics`
opens a screen straight away), `stop` quits him, `log` shows his log, `look` switches to the
camera view and `shot` saves a screenshot into `export/cardputer/`.

HAL Zero needs the SDL2 runtime (`libsdl2-2.0-0`), `rpicam-vid` and a PipeWire session on
the Cardputer. The stock image on our unit had all three.

## 7. Let the two HALs talk (optional)

1. On the desk HAL's card, set `link=on` in `/hal/config.txt`. He then stays on Wi-Fi and
   announces himself as `hal9000-old.local`.
2. Put his half of the conversations on the card: run `make_voice.py --dialogues` (step 6.3),
   then the `--copy-to` command from step 4 again.
3. HAL Zero's settings file already has `link=on`. Both devices must be on the same network.
4. On the Cardputer press **D** and pick a conversation. HAL Zero's status panel shows
   `LINK READY` when he has found the desk HAL, and `SEEKING` while he is looking.

If HAL Zero's diagnostics screen says the desk HAL's firmware is too old, flash the desk
HAL again (step 5): both should be on the same version.

## 8. The simulator and screen previews (optional)

HAL Zero also runs in a window on your computer, which is the quickest way to try changes:

```bash
~/.platformio/penv/bin/pio run -e sim
```

```bash
.pio/build/sim/program --root build/new/hal
```

Keys are the same as on the Cardputer, with real arrow keys. To save every screen as a PNG
without opening a window:

```bash
.pio/build/sim/program --shots /tmp/zero
```

```bash
.pio/build/sim/program --shots /tmp/desk --layout cores3
```

The simulator and the Cardputer build share the `.pio` folder, and building one clears the
other's program. Run `pio run -e sim` again after a Cardputer build, and
`tools/cardputer.sh build` again before the next `deploy`.

## 9. The AI brain (optional)

The brain is a small program on your computer that answers as either HAL, in his voice,
using an AI model. It is being built for v0.6: today you can talk to both HALs from the
computer; chatting on the Cardputer itself comes next.

It needs step 3 (the voice tool) and:

- **A model.** By default the brain uses [Ollama](https://ollama.com), which runs the model
  on your own computer: nothing you say leaves it. Install Ollama, start it, and get a chat
  model:

  ```bash
  ollama pull qwen3.6:35b-a3b
  ```

  That is the model used here (a 24 GB download that wants about 32 GB of memory). On a
  smaller computer pull a smaller chat model and name it in the settings file (below).
- **Ears (only for speaking to HAL).** whisper.cpp's `whisper-cli` and its English model,
  488 MB, from Hugging Face:

  ```bash
  mkdir -p brain/models && curl -L -o brain/models/ggml-small.en.bin https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-small.en.bin
  ```

**Settings** are optional. To change the model or the port, copy the template and edit the
copy (git ignores `brain/.env`, so keys you put there stay on your computer):

```bash
cp brain/env.example brain/.env
```

**Start it and ask something:**

```bash
tools/brain.sh start
```

```bash
tools/brain.sh ask zero "What do you think of the old model?"
```

```bash
tools/brain.sh ask desk "How are you feeling today?"
```

Each prints the reply and plays it in that HAL's voice. The first answer after starting
takes 10–15 seconds while the model loads; after that, about a second. `tools/brain.sh stop`
stops it, `status` says whether it is running, and its log is `brain/.run/brain.log`.

- Until it is paired with HAL Zero the brain only answers requests from this computer.
  `tools/brain.sh pair` (which shares a key with HAL Zero and opens the brain to your
  network) is for the Cardputer chat that comes next; you don't need it yet.
- The brain's own tests need no model, voice or microphone:
  `tools/.venv/bin/python -m unittest discover -s brain -t . -p 'test_*.py'`

## Updating

```bash
git pull
```

Then repeat only what changed: render the voice again if `content/` changed (steps 3, 4 and
6.3), flash the desk HAL (step 5), and build and deploy HAL Zero (steps 6.2 and 6.4).
`CHANGELOG.md` says what each version changed.

## If something goes wrong

| What you see | What to check |
|---|---|
| "I can't find my memory, Dave" | The card is missing, isn't FAT32, or has no `/hal/voice/` (step 4) |
| HAL's clock is wrong or greetings come at odd times | `wifi_ssid`, `wifi_password` and `timezone` in `/hal/config.txt` |
| The upload can't find the CoreS3 | A charge-only cable, or the CoreS3 needs download mode (step 5); on Linux, serial permissions (step 2) |
| `tools/cardputer.sh` asks for a password or is refused | Key login isn't set up (step 6.1) |
| `tools/cardputer.sh build` can't connect to Docker | Docker isn't running: start Docker Desktop (macOS) or the Docker service (Linux) |
| `tools/cardputer.sh deploy` can't find the program | A simulator build cleared it: run `tools/cardputer.sh build` again (step 6.2) |
| HAL Zero shows `LINK SEEKING` forever | The desk HAL is off, has `link=off`, or is on another network (step 7) |
| A copy to the Cardputer was interrupted | Run `tools/cardputer.sh deploy` again; the program is only swapped in once fully copied |
| `tools/brain.sh ask` says `error=no-model` | Ollama isn't running, or the model in `brain/.env` (or the default) isn't pulled (step 9) |
| `tools/brain.sh start` says the brain didn't start | Read the end of `brain/.run/brain.log`; if port 9100 is taken, set `HAL_BRAIN_PORT` in `brain/.env` |
